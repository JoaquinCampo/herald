# Return to the outcome population

The fixed generic numeric predictor failed locked study041. Close functional
probe variants in the four-key, single-answer Knorm .10 population. Do not
invert its sign or tune its cue, digit selection, model or penalty.

Four competing explanations motivate a population check before another feature:
1. The single-answer score hides partial retrieval damage behind a binary label.
   Asking for four values yields partial-credit losses that may vary smoothly.
2. Native Knorm remains too destructive even with a milder action. The new
   population would still cluster at total loss and should be rejected.
3. Ordinary model retrieval error dominates the multivalue task. Low reference
   quality would make this a poor small diagnostic of compression damage.
4. There is adequate graded variation but existing observations contain little
   useful information. A viable population alone cannot establish predictability.

essay haystack, one key, four seven-digit values, one queried key, length4096,
seed2026090644. Retain the official template and source provenance. Require no
exact prompt or raw-context overlap with any previous v4 manifest. No selection
by answers, model confidence or outcomes. This population is development only.

Knorm .05, a single milder action chosen before observing these outcomes because
.10 single-answer losses were near saturation in several fresh batches. This
changes task and action deliberately to find an assay, not to isolate which
change caused a difference. Do not run a severity sweep.

Reference is the full independent B0 cache, action is a native compressed clone,
and noop must exactly reproduce reference. Both use the same original greedy
128-token horizon. Apply pinned official string_match_all: each of four answer
values contributes one quarter to score. Signed loss is ref score minus action

references, at least4/16 strictly partial positive losses (0<loss<1), at least

are assay criteria, not a prediction gate. Report the whole empirical score
and signed-loss distribution, without dropping any unsuccessful or failed case.
Any technical failure must be fixed by reproducing its original failing case
before interpreting or expanding. If viability fails, do not fit a predictor or
search another severity on these outcomes; return to task/intervention choice.

If viable, inspect the task mechanism and choose one prospective observation
with a new discovery/evaluation/confirmation design. Preserve the requirement
of meaningful signed-loss regression gains over matched information baselines,
uncertainty and measured cost. A better outcome distribution is not HERALD
