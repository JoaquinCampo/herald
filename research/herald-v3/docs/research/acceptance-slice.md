# Minimal real acceptance slice

Status: executable specification, not executed evidence. Owner alone launches GPU work. This milestone requires no installation or training.

Use eight declared engineering prompts from exposed IFEval development material, including multi-instruction cases. Save their exact bytes, scorer kwargs, model/tokenizer revisions, environment, dtype, attention backend, seed, template, total token budget, and action configuration before running. Keep a ledger of early-EOS and failed cases; if fewer than four reach token 32, enumerate additional engineering prompts under the same selection rule. No inference claim comes from this convenience set.

1. **Preserve the real boundary.** Generate the full-cache prefix once. Store token IDs, pending token, layer KV tensors, cache position, attention mask, logical sequence length, positional/rotary metadata, model state and RNG state where applicable. Let P be the tokenized prompt length. Assert pre-action KV length P+31 at each layer, pending token equals generated_ids[31], and the common committed output prefix is generated_ids[:32]. The continuation processes this pending token at absolute position P+31 and predicts generated output index 32 (token 33). The inherited v2 `s=32` helper makes token 33 pending instead; adapt it explicitly rather than reusing the number.
2. **Distinguish competing explanations first.** An output discrepancy could be compression damage, aliased mutable state, off-by-one token handling, runtime nondeterminism, or a scoring bug. The cheapest distinguishing sequence is two uncompressed forks, a zero-removal action, reversed branch execution order, then actual eviction. Compare uncompressed runs to an uninterrupted reference. If no-op parity fails, stop before compressed interpretation.
3. **Prove independence and transparency.** Compare tensor contents and all decoder-state fields, not just pointers. Mutating the treatment copy must leave the saved reference unchanged. Two uncompressed forks and the uninterrupted reference must match token-for-token to termination and score identically. Probe-on and probe-off outcome continuations must match for each action. JS of two matched no-op distributions must be zero within a frozen numerical tolerance (proposed absolute 1e-6), with finite normalized probabilities. Save max probability/logit discrepancy, not only a pass flag. Any tolerance change requires a documented runtime diagnosis before action results are read.
4. **Exercise real compression and scoring.** Apply the verified direct live-cache Knorm transform to the cloned cache for .25 and .50 before processing the pending token. A Knorm context around a one-token decode is insufficient because a prefill-only hook may not evict. Record kept index sets and prove actual per-layer KV sizes and bytes decrease before measuring pa. Independently continue to EOS or the common budget, and save complete answers plus both scores and d. Assert d=q0-qa without clipping labels. Compare instruction-level pass vectors to the pinned official IFEval scorer for every generated response and hand-checked fixtures covering positive, negative and zero signed differences. Exact scorer parity is required; a fixture alone does not validate generation or labels.
5. **Account for the measurement.** Time state copying, compression, the three sandbox forwards, JS reduction, and continuation separately with device synchronization. Measure peak memory with and without probes and reference-state preservation. Report measured cost even if prediction later fails. Repeating the same short prompt is a timing diagnostic, not more independent scientific data.

Engineering pass requires all eligible cases to satisfy independence, token parity, probe transparency, scorer agreement, finite features, and complete provenance. Missing artifacts or exceptions are failures requiring diagnosis, not silent row exclusions. A compression action need not change the answer on these eight prompts. Outcome variation is assessed in the pilot, not forced in the smoke test.

If a check fails, retain the exact failing artifacts, state the competing explanations, run the cheapest distinguishing check, and immediately rerun the original failure after the fix. Only then broaden verification. If ExpectedAttention is later added, separately establish no-press re-prefill versus live-reference parity and pressed versus matched sham semantics; it is not covered by Knorm acceptance.

The owner's launch evidence should include an environment/source manifest, per-prompt parity records, scorer comparison, action evidence, timing/memory report, and artifact SHA-256 manifest. CPU fixtures may precede this run but cannot substitute for the intended model's real paired workflow.
